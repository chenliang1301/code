## 二、Tennis-Vision 故障记录

### TV-01：NaN 坐标导致程序退出

**现象**：900 帧处理到 `[8/9] Classifying shots...` 时退出。

```text
utils/serve_detector.py → is_serve()
utils/bbox_utils.py → get_center_of_bbox()
ValueError: cannot convert float NaN to integer
```

**原因**：传入的球框含非有限坐标，计算中心时调用 `int()` 崩溃。代码检查发现，TrackNet 整段无检测时，原插值逻辑仍会生成 NaN 球框，导致缺失数据继续进入事件分析。初次 900 帧日志没有提供原始网球检测阶段，不能断言当次也一定由缺少权重造成；后续 150 帧日志明确确认了权重缺失和零检测。

**本地修改**：

- `main.py`：过滤无效网球框；整段无有效检测时明确停止。
- `trackers/tracknet_ball_tracker.py`：空输入返回空列表，全无效输入保持逐帧空检测，不生成 NaN 球框。
- `utils/serve_detector.py`：发球判断拒绝无效球框或球员框，防止坐标转换崩溃。
- `tests/test_serve_detector.py`：新增非有限球坐标和球员坐标的回归测试。

**验证**：修改文件语法检查通过；13 项发球检测测试通过依赖隔离执行。未验证完整视频流水线。用户后续日志触发了新增的 `No valid ball detections` 提示，说明 Linux 已包含对应停止逻辑，但不能由此确认其他文件也全部同步。

### TV-02：TrackNet 权重缺失

**日志时间**：用户提供的日志为 11:19:04，未单独注明日志日期。

```text
TrackNet weights not found at 'models/tracknet.pt'
TrackNet model not loaded - returning empty detections
Raw detections: 0/150 frames (0.0%)
```

**根因**：配置启用了 TrackNet，但所配置路径下没有权重。模型没有加载，不能进行网球检测。这与已加载模型后的检测精度问题不同。

**处理步骤**：在 Linux 项目根目录和对应环境中执行：

```bash
conda activate tenvis
cd /home/cl/code/aidemo/Tennis-Vision
python -m pip install gdown
mkdir -p models
gdown 1XEYZ4myUN7QT-NeBYJI0xteLsvs-ZAOl -O models/tracknet.pt
```

以上下载命令来自仓库现有提示，本次未执行下载，也未确认外部链接当前可用。若下载遇到权限、配额或网络问题，应保留完整日志，不能将下载得到的网页文件当作权重使用。

配置检查：

```yaml
pipeline:
  use_tracknet: true
models:
  tracknet: "models/tracknet.pt"
stubs:
  use_ball_stubs: false
```

**完成标准**：日志不再出现模型未加载提示，模型实际推理成功，并检查原始检测率与定位画面。检测率大于零只表示有输出，不代表定位准确。

### TV-03：空结果缓存影响复测

日志显示空检测被写入：

```text
tracker_stubs/ball_detections_tracknet__tennis_1612384.pkl
```

若后续开启缓存，可能继续读到这次失败运行的空结果。修复权重后先设置 `stubs.use_ball_stubs: false`，重新运行实际检测，确认日志没有复用旧缓存。不需要为此删除整个缓存目录。

**总结**：缓存加速不能代替模型加载检查；下载好权重后还需确认结果来源是重新推理。

### TV-04：球场标定验证失败

```text
line support 0.062 < 0.22
only 0 of 12 sampled frames lie on painted court lines
```

模型输出的关键点没有通过实际白线支持度检查。当前无法确定是视角、画面内容、缩放、模型泛化还是模型配置所致，需要查看原视频和关键点叠加结果。

**影响**：球场坐标、距离、球速、小球场映射及依赖它们的三维分析不可信。

**下一步**：先选连续、球场完整可见的片段验证；检查场地权重路径及实际加载模型；抽取多帧叠加关键点和预测球场线。不要通过调低有效性阈值把错误标定变成通过。

## 三、yolov8_pose 技术限制与待实现项

这些条目来自方案讨论和代码检查，不是已复现的运行崩溃。

### YP-01：姿态接口不一致

Tennis-Vision 的姿态分类使用肩、腕等带相对深度的坐标；本项目 `keypoints[17][3]` 表示 `x,y,conf`。第三项是关键点分数，不是深度，不能直接替换进入 `(x,z)` 身体轴公式。

建议采用二维短时序特征、人工持拍手配置、视角校准和质量拒绝；侧身、遮挡或肩线退化时输出未知。

### YP-02：正反手统计必须按事件去重

正反手连续出现多帧不能每帧加一。方案采用“准备→引拍→挥拍→恢复”状态机，在完整事件确认时提交一次计数。仅姿态版本统计挥拍，实际击球计数还需接触证据。

计数功能尚未编码；没有板端精度或实时性能结果。RK3568 模型部署支持不能等同于网球任务验收通过。

### YP-03：预览集成注意事项

- 当前摄像头处理有固定逆时针 90° 旋转，需要匹配实际安装方向。
- 当前 ROI 涉及目标筛选和显示，不代表 NPU 只推理 ROI。
- 画面会恢复 ROI 外原图，计数 HUD 应在恢复后、JPEG 编码前绘制，避免被覆盖。
- `draw_text()` 和 OpenCV 默认 `putText()` 字体不能直接满足中文显示；首版可用 FH/BH，中文需另加字库方案。
- 不能用检测数组下标表示人物身份；多人或身份不确定时应暂停归属。

详细方案见 [正反手分析、计数与预览方案](examples/v8_pose_1.0/TENNIS_STROKE_ANALYSIS_PLAN_ZH.md)。

## 五、当前建议处理顺序

1. 在 Linux 准备正确 TrackNet 权重，关闭旧球缓存并短片段重跑。
2. 确认网球模型真正加载、坐标有限、检测位置合理，不再出现 `nan%`。
3. 检查球场关键点及球员 ID 叠加，解决两项有效性检查失败。
4. 再检查事件、球速、三维输出；运行完成不等于统计可信。
5. 使用可靠数据评估正反手识别，决定是否实现 RK3568 轻量计数功能。

## 六、经验总结

- 首先找 traceback 最后一条异常，区分警告、数据有效性失败与真正退出原因。
- 缺失数据应保持缺失或明确拒绝，不能插值成 NaN 后继续分析，也不能填零伪装有效检测。
- 模型文件存在、成功加载、有检测输出、定位正确，是四个不同检查阶段。
- 无效数据会层层传播：无球数据可能污染轨迹、事件分类、发球判断和计数。
- 依赖球场和身份的指标必须先通过各自有效性检查。
- 按事件统计动作，按时间戳计算运动，不能按帧数直接累计或固定推断速度。
- 清楚区分“代码已修改”“局部测试通过”“目标环境重跑通过”和“业务结果达到要求”。
