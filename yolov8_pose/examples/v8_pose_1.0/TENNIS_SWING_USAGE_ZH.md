# 姿态挥拍计数使用说明

本示例已加入实验性单人正反手挥拍计数。它识别人体动作，不检测球拍或网球，空挥也可能计入。真实场景准确率和 RK3568 端到端性能尚未验收。

## 构建和启动

使用本项目原有 RK3568 Linux 交叉编译流程，示例目录为 `examples/v8_pose_1.0`。CMake 已显式加入 `tennis_analyzer.cc` 并安装 configs 目录。部署时须更新整个示例可执行文件和配置，不能仅复制一个源文件。

在安装目录启动，模型文件名按实际部署调整：

```bash
./rknn_yolov8_pose_demo model/yolov8n-pose.rknn camera 0 8080 --tennis-config configs/tennis_pose.conf
```

不传 `--tennis-config` 时仍为原有姿态预览。网球模式仅支持相机输入，单图不支持计数。当前没有新增视频文件解码入口；离线测试使用关键点回放工具。

修改配置中的 `handedness=right/left` 和 `rotation=0/90/180/270`。旋转单位是顺时针角度，默认 270 等于旧程序逆时针 90 度。先保证人体直立、腕肘清晰可见。路径相对启动目录，启动时配置或日志路径不可用会报错，不会静默禁用。

## 校准与计数

### 精简界面更新

主工具栏仅保留“下一步引导”和“暂停”。引导按钮按当前状态依次提供单人全画面ROI、采集正手、采集反手和开始/恢复计数；采集中禁用重复启动。ROI编辑、文件保存/加载、重采和清零放在折叠的“更多设置”中，不再显示重复菜单。

默认每类改为3个有效样本（已有配置需同步更新）。重复发送正在采集的同类命令不会清空已采样本。准备位恢复容差由0.4调整为0.6个躯干长度，减少姿势轻微变化造成卡住；仍需回到准备位置并停顿。拒绝原因细分为窗口无效/峰值在边缘、动作过短、路径太小。减少样本只降低初次操作负担，不代表识别精度提高；真实动作仍需验证，差异较大的训练动作应补充样本或重新校准。

下方旧版本按钮说明仍可用于“更多设置”内相同功能，网页实际引导优先。

### 最简操作与样本为0的调试

新版配置默认 `debug=true`。重新编译部署程序及配置后，网页直接点击“全画面ROI”（确保只有一人）→“①采集正手”→完成样本→“②采集反手”→完成样本→“③保存校准”，无需反复选择下拉菜单。更改ROI会清空校准；多人场景仍需绘制ROI。

网页实时显示当前步骤和调试数值。终端每2秒打印一行 `tennis DEBUG` JSON，即使状态不变化也打印，便于排查一直为0：

- `pose_ok=false`：先看 `pose_issue` 的缺失点，露出肩髋肘腕；不要只拍脸。
- `LOST`：保持准备姿态静止半秒，观察腕速是否一直高于停止阈值。
- `READY/PREPARE`：腕速没有超过 `start_speed` 时不会形成完整挥拍，检查动作幅度和腕点。
- `SWING`：随挥后需要降速并停顿；否则会达到动作超时。
- `RECOVER`：回准备位距离必须小于0.4，再停顿；一直停在随挥末端无法开始下一次。
- `rejected`增长：结合 `reason` 检查动作超时、路径太短或没有速度峰值。
- `CONFIRM TARGET`：正常计数仍需确认身份；采样模式短暂失去姿态后会自动重新稳定，减少反复点击确认，但丢失的半个动作不计入样本。

`debug=false` 可关闭周期性终端输出与网页详细数值，不改变识别阈值。调试模式不会绕过质量检查或强制增加样本。实际零样本根因仍需现场日志确认。

网页现已提供中文操作说明、实时状态区和命令执行反馈。点击命令后先返回执行编号，随后轮询确认成功或失败；“排队”不是“采样完成”。状态每秒刷新，超过 3 秒未更新会提示采集/推理可能阻塞。

1. 打开 `http://开发板IP:8080/`，画多边形并点击 Apply，将一名训练者包含在 ROI 中。多个人同时进入时暂停分析，不自动切换计数对象。
2. 在网页新增的 Tennis 下拉框选择 `Collect FH`，点击 `Tennis command`。训练者先保持准备姿态约半秒，然后完整挥正手、停顿并恢复，重复至画面 `SAMPLES FH` 达到配置值（默认 5）。采集阶段不累计 FH/BH。
3. 选择 `Collect BH`，同样采集反手。每次完整挥拍后应恢复并停顿；连续快速挥拍不是本版优先场景。
4. 两类样本通过留一可分性检查后进入 RUNNING；若提示 `CLASSES NOT SEPARABLE`，调整机位/动作并重新采集，不强行输出类别。选择 `Save calibration` 保存。
5. 运行期间画面显示 FH、BH、UNKNOWN、最近类别、状态及样本数。UNKNOWN 表示完整挥拍与模板不够匹配或类别间距不足；被取消的候选不会算成 UNKNOWN。
6. 选择 Pause 暂停；Start / Confirm 恢复并重新稳定。目标丢失、关键点不足或采样长间隔可能要求确认，这是保守保护，不能在换人后直接当作原训练者继续。
7. Reset counts 会清空计数，保留兼容校准；事件编号保持单调递增，便于区分复位前后日志。

重启后，先应用 ROI，再 Load calibration，然后确认机位、训练者和姿态模型未变，点击 Start / Confirm。校准文件校验格式、持拍手、旋转和样本可分性，但当前未自动绑定模型哈希或相机身份，因此更换模型、分辨率、训练者或机位后必须重新采集。

修改 ROI 会清空动作历史和模板，保留计数并要求重校准。当前为完整关键点窗口保守实现，关键点缺失会取消候选，未使用缺失掩码补全、自动持拍手推断或三维身体轴。

## 日志与回放

### 通过终端查询状态和发送命令

部署新版程序后，安装目录中的 `tools/tennis_control.py` 可用于诊断，只依赖 Python 3 标准库。开发板没有 Python 时，可从同一局域网的电脑通过 `--url` 访问。

```bash
# 当前状态及下一步建议；将 IP 替换为开发板实际地址
python3 tools/tennis_control.py --url http://192.168.1.100:8080 status

# 每秒查询，Ctrl+C停止；不改变任何计数
python3 tools/tennis_control.py --url http://192.168.1.100:8080 watch

# 先在网页绘制并应用 ROI，然后开始正手采样（清空正手旧样本）
python3 tools/tennis_control.py --url http://192.168.1.100:8080 calibrate_fh --yes

# 正手样本达到目标后采集反手
python3 tools/tennis_control.py --url http://192.168.1.100:8080 calibrate_bh --yes

# 样本齐全且可分后保存；下次先应用ROI再load，确认机位相同后confirm
python3 tools/tennis_control.py --url http://192.168.1.100:8080 save
python3 tools/tennis_control.py --url http://192.168.1.100:8080 load
python3 tools/tennis_control.py --url http://192.168.1.100:8080 confirm

# 暂停、恢复、清零
python3 tools/tennis_control.py --url http://192.168.1.100:8080 pause
python3 tools/tennis_control.py --url http://192.168.1.100:8080 start
python3 tools/tennis_control.py --url http://192.168.1.100:8080 reset --yes
```

发送采样命令只代表进入采样阶段，仍需要人在镜头前完成挥拍。脚本等待的是命令执行确认，不会等待五次挥拍全部完成；之后通过 `status/watch` 查看 `fh_samples`、`bh_samples` 进度。

没有脚本也可使用 curl：

```bash
curl -sS http://192.168.1.100:8080/tennis/status
curl -sS -X POST http://192.168.1.100:8080/tennis/pause
# POST返回id且HTTP 202仅代表排队，随后GET检查commands数组对应id的result
curl -sS http://192.168.1.100:8080/tennis/status
```

诊断 JSON 的 `state` 包含状态、动作阶段、ROI人数、姿态质量、具体缺失点提示、校准进度、计数、分析频率与下一步建议。`age_ms` 为最近一次分析状态发布距今时间，`pending` 为待执行命令数，`commands` 为最近32条已执行结果。结果过旧或命令超时不能视为成功，不要立即重发会清空样本的命令。

程序终端输出 `tennis command=<编号> ... result=OK/REJECTED` 和变化后的 `tennis state:`。调试时保存日志：

```bash
./rknn_yolov8_pose_demo model/yolov8n-pose.rknn camera 0 8080 --tennis-config configs/tennis_pose.conf 2>&1 | tee tennis_run.log
```

### 常见误用与排查顺序

| 表现 | 检查/处理 |
|---|---|
| 只拍到脸或上半身，采样一直为0 | 后退或调整镜头，双肩、双髋、持拍侧肘腕必须入镜。截图中脸部近景不适合挥拍分析。 |
| `enabled=false` 或命令HTTP 409 | 未带 `--tennis-config` 启动；停止旧进程并按网球命令启动。 |
| 状态接口404或不是JSON | 可能是旧程序/错误端口。重新编译部署新版可执行文件并刷新页面。 |
| ROI人数为0 | ROI未应用、人体框中心不在ROI内、人体未检测到；先检查画面方向、全身距离和ROI位置。 |
| ROI人数大于1 | 缩小或移动ROI，只保留一名训练者。 |
| 提示缺少肩/腕/髋 | 查看具体点名；检查遮挡、光照、衣物及画面裁切，不要先降低质量阈值。 |
| `LOST`不进入`READY` | 核心点需稳定可用；保持初始准备位至少半秒，避免一直挥手。 |
| 采样命令成功但数量不变 | 命令只启动采样。等READY后完整挥拍，再停顿；检查`reason`与拒绝数。 |
| `NO SWING PEAK` | 动作速度不足或腕点不稳定，先检查画面和回放，再考虑调阈值。 |
| `SHORT / INCOMPLETE MOTION` | 幅度太小、动作太短或轨迹不完整；完整引拍与随挥。 |
| `ACTION TIMEOUT` | 动作一直未降速/点位抖动；挥拍后停顿并检查曝光和遮挡。 |
| 一次后停在`RECOVER` | 持拍手没有回到最初准备位置；返回原位并停顿，不能只在随挥末端保持静止。 |
| `LONG GAP` / 要求确认目标 | 帧间隔超过max_gap；先检查相机/推理耗时，查询analysis_hz和age_ms，再确认同一人。不能无限放宽间隔掩盖丢帧。 |
| 样本齐全但不能开始 | 两类模板可分性不足；重新采集差异清晰的完整动作或调整机位。 |
| 保存失败 | 校准未通过，或路径/写权限错误；查看命令具体结果。 |
| 加载失败 | 文件不存在、格式无效、左右手/旋转不兼容或样本不可分；重新校准。 |
| `UNKNOWN`较多 | 机位或动作与模板不一致、质量不足；先核对模板与人物，不直接把未知强分正反手。 |
| 长时间只有“排队” | 查看age_ms、pending和进程终端，采集/推理可能阻塞；结果未知时不要反复点击采样。 |

诊断提示来自关键点、输入人数与状态机，不能自动确认拍摄机位正确或动作标准；姿态可用也不等于识别一定准确。

默认在启动目录追加 `tennis_events.csv`，包含会话头、控制命令及已提交事件。控制记录和事件记录不同格式，读取时按首列区分。日志使用单调时间戳，不能当作当地日期；会话头另有系统时间。日志失败会在画面提示；异常断电不保证恢复计数，重启默认新会话。

可在配置中添加以下项，录制用于调参的姿态，不保存原始视频：

```ini
pose_path=tennis_pose_replay.txt
```

姿态文件每次启动覆盖，达到约 100 MiB 停止录制并在终端提示。应使用独立路径备份重要数据。记录 ROI 变化和控制命令；多人歧义帧记录为空检测。它适合算法复现，不代替原视频人工标注。

在有 C++11 编译器的桌面 Linux 或开发板上，可独立构建，无需 OpenCV/RKNN：

```bash
g++ -std=c++11 -O2 cpp/tennis_analyzer.cc tools/tennis_replay.cc -o tennis_replay
./tennis_replay configs/tennis_pose.conf tennis_pose_replay.txt

g++ -std=c++11 -Wall -Wextra -Werror cpp/tennis_analyzer.cc tests/tennis_analyzer_test.cc -o tennis_test
./tennis_test
```

回放中的 `@save/@load` 会访问配置指定校准路径，使用独立测试配置避免覆盖现场模板。回放输出事件和最终计数；人工核对事件时间和动作类别，不能只看总数接近。

## 已验证与待验证

- 本机 MinGW C++11 严格警告编译通过：分析核心、回放工具及核心测试。
- 合成轨迹测试覆盖：正反手采集/分类、校准保存/加载及左右手不兼容拒绝、重复帧、暂停/重置、NaN、长时间间隔及 ROI 清空。
- 新增操作反馈测试覆盖：未应用ROI就开始/采样、未校准保存、未知命令拒绝、缺失手腕诊断；Python命令行5项测试通过，网页JavaScript语法检查通过。
- Windows 未验证 Linux socket 服务、RKNN/OpenCV 整体链接、网页到摄像头的端到端效果或板端速度；需在目标工具链构建和 RK3568 上实测。

当前实现是详细设计的首个规则/模板基线：固定阈值可配置，尚未实现静止噪声自适应阈值、完整肘角/双手特征、每维稳健尺度、低采样率独立门控及网页样本逐条人工确认。应先录制现场姿态检验基线，再依据漏计/误计证据补充算法。不能将合成测试通过解释成真实网球识别准确率达标。
